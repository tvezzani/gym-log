# Milestone 6 plans, settings and administration verification

Implemented in the active Ubuntu WSL checkout, following the existing charcoal/yellow React/SCSS interface. Today, History, Plan and Settings are the main tabs. The menu exposes My exercises, password/logout, and account/catalog management for admins. There are exactly two roles, user and admin; admin controls never expose another account's sets or plans.

## Reproduce

With the development PostgreSQL service running, run `npm run check`, `npm run test:db` and `npm run test:web` from the repository root. Chromium installation and local startup commands are in `apps/web/README.md`. `apps/web/test/management.integration.ts` uses three isolated browser contexts, the actual API, built frontend and a disposable migrated PostgreSQL database. It removes the database afterward and does not create real family accounts or modify development history.

## Recovery limits and remaining work

Forms live only in the running page; no offline queue or browser storage is added. Navigation/session expiry preserves drafts, and reauthentication stays bound to the draft owner. Set drafts retain their original timezone so changing preferences cannot reinterpret an unsaved instant. Plan create has no idempotency key: after an unknown outcome, review the saved list before starting another entry. Account creation can be checked by username in the refreshed list; an uncertain reset can be repeated with the same temporary password, revoking sessions again.

Actual family phone/browser software-keyboard and touch checks remain open. Private HTTPS/Tailscale hosting, persistent deployment, backups, restart tests and a verified restore are milestone 7. No production deployment or real gym visit is claimed by these local browser results.
